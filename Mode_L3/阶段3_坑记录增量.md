接 `Mode_L1/开发坑记录.md` 的 A/B/C/D 编号体系：本阶段求解器与流程新踩的 9 条（A15–A20、B5–B7、C4–C5、D5），另加一栏独立的 **GUI 坑记录（G1–G23，2026-10-29）**。每条给「症状 / 根因 / 早发现的办法 / 处置」。**这些坑都是"错得不响"的类型 —— 不抛异常、数还好看。**

## A 类：静默错（结果错但程序不报）

### A15　近 n_a 的模簇被整簇漏掉（K = 43，解析 48）
**症状**：w=50 的侧模个数 43，`⌊2V/π⌋+1` = 48；放宽 `n_roots` 到 200 仍 43（说明不是截断）；最上面一阶落在 n_a−1.47e-4，而解析基模应在 n_a−4.2e-6。
**根因**：`scan_newton` 用「|f| 的局部极小」取种子。这一簇模的 Im N ≈ 2e-5 与模间隔同量级，|f| 在实轴上形不成谷（实测窗口 min|f| = 21.6、median = 42.9），于是整簇没有种子 —— 不是根不存在，是**没人去找**。
**早发现**：把 K 与解析模数逐格对比（A6 的整数断言）；或对实轴做一次 `real(f)` 变号计数（本例 7 次，与解析一致，说明根都在）。
**处置**：`find_roots_complex` 加两条 opt-in 种子 —— 变号区间中点（`seed_bisect`）+ 复平面平移 `x0 + i·Im(n_a)`（`seed_imag`）；`e3_lateral_solve` 里打开。修后 K = 48，最高三阶 2.41691482（n_a−4.08e-6，与解析 4.19e-6 吻合）。**缺省路径不动**，阶段 2 的数一位没变（A0 逐位 PASS 可证）。

### A16　非均匀网格的近重合节点：1/h² 爆到 1e30
**症状**：同一个稀疏算子两次调用给出**不同的本征值谱**；`eigs` 认不出 2.4169 而是 2.4394；换成 x 方向均匀 20 nm 的旧实现又是另一个数。
**根因**：界面坐标由「总厚度 − 累加和」算出，与分段端点只差 1 ulp（~1e-16 μm）。两个几乎重合的节点让差分的 1/h² ≈ 1e30，整张矩阵被污染成垃圾。
**同源变体（更隐蔽）**：`e3_field2d` 的并集 y 网格里也出现 `min(diff(ys)) = 2.2e-16`，`trapz` 权重塌成 1e-16，那一行在加权求和里等于不存在 —— 不报错、结果只偏几个百分点。
**早发现**：建完网格先打印 `min(diff(x))`；两次建同一个算子比较谱是否逐位相同。
**处置**：`ys = unique(round(ys(:)*1e7)/1e7)`（量化 0.1 nm），并把 `min(diff)` 打进日志。修后 y 网格最小间距 3.43e-4 μm，重复调用谱逐位相同。

### A17　坐标约定反了，但数"恰好"对
**症状**：二维场的竖剖看起来峰值不在 QW；层功率表却给出 n-clad 99.7%（这个"99.7%"是我取错窗口的产物，不是模型错）。
**根因**：本工程的 y 一律**自衬底界面向上**（y=0 在衬底，y=1.729 在 p-clad 顶面），不是施工单文字里的「自 p-clad 顶面向下」的 y′。QW 在 y∈[1.320, 1.329]，1D 模场峰值在 y=1.287（QW 上方 34 nm，物理正确）。
**为什么差点被骗**：T4 的 Γ 窗口、二维场的 y 网格都用了 `layer_bounds`（同为自底向上），所以**两条路径同时"错得一致"**，Γ(2D) 与 Γ(1D) 仍然对得上 —— 一致性检查抓不到同向的约定错。只有把图和物理剖面并排看才发现。
**早发现**：任何涉及「深度」的公式，先用一个可自查的锚点核对：本结构里 p-clad 顶面 = 中间层总厚 = 1.729 μm，QW 应在 y = 1.729 − 0.409 ≈ 1.320。
**处置**：`t4_field.m` 纵轴改正常方向、标签写明「自衬底界面向上」、p-clad 顶面参考线画在 y=1.729；csv 表头 `yprime_um` → `y_um`。

### A18　结构体数组模板字段不齐 → 报 ERROR 而不是 FAIL
**症状**：`ERROR in t5_sweep: 在不同结构体之间进行下标赋值`，40 格扫描整段没跑，但日志只当异常记了一行。
**根因**：`D.tab` 的模板 `struct(...)` 少了 `na/Ga/okA7` 三个字段（`r` 里新增了），赋值时 MATLAB 要求字段完全一致。
**早发现**：凡 `D.tab(k) = r` 这种写法，模板必须与 `r` 一起改。
**处置**：模板补成 `struct(..., 'ratio',{},'sec',{},'na',{},'Ga',{},'okA7',{})`；`run_all` 把脚本异常记成 FAIL（而不是静默 ERROR），否则 FAIL=0 会被误读成"全过"。

### A19　`imagesc` 把非均匀坐标按等间距铺开（图与数据"对不上"）
**症状**：`field2d_w3.png` 里模场峰值画在 y≈0.6 处，而同一份数据里 `argmax` 在 y=1.287、Γ=0.02671 也对——图和 csv 像是两张皮。
**根因**：`e3_field2d` 的 y 网格是非均匀的（QW 附近 1 nm、远场 25 nm）；`imagesc(x, y, C)` 只把 `y` 当**两端范围**，行仍按等间距铺开，于是第 246 行（真值 y=1.287）被画到 −0.87+245/553×3.34≈0.61。
**判据**：用 `max(sum(E2,2))` 取峰值行得到 1.287，与图上亮度峰位置差 0.6 μm ⇒ 立刻怀疑绘图，不要怀疑求解器。
**处置**：非均匀坐标一律 `surf(x, y, zeros(size(C)), C, 'EdgeColor','none'); view(2); axis tight`（顶点坐标精确），或先把数据重采样到均匀网格再 `imagesc`。这次同时把峰值行画成白色实线，图与数就对得上了。

### A20　把向量喂给 `sprintf` 会按格式串循环复用参数（标题拼成两遍）
**症状**：`field2d_w3` 的标题变成 99 个字符，前后各一遍、第二遍数字是 `w=0.0 y=0.025`。
**根因**：`C.Gamma` 是 1×K 向量（K=3 阶模），`sprintf(fmt, w, ypc, C.Gamma)` 展开成 5 个参数，格式串 3 个占位符 → 第二遍用 `Gamma(2)`、`Gamma(3)` 去填 `%.1f`、`%.3f`，第三遍占位符没参数就留空。
**处置**：标量字段一律写明下标（`C.Gamma(1)`）；`sprintf`/`fprintf` 前先 `numel()` 一次；`strlength` 与预期长度不符时先查参数个数。

## B 类：求解器与线代

### B5　`eigs(A, k, 'la')` 在本机对 ~1e3 阶稀疏矩阵整体返回 NaN
**症状**：本征值全 NaN，无警告。
**处置**：`la` 一律不用；改 shift-invert（`eigs(A, k, sigma)`）。乘 dx² 缩放能绕开 NaN，但 `la` 拿到的是最高阶箱模，不是导模 —— 绕开了也没用。

### B6　shift-invert 的移位点必须落在导模带里
**症状**：FD 找到 12 个本征值，芯内功率占比**全是 0.00000**，N 随 w 几乎不变。
**根因**：移位点取 `0.995·max(Re n)` = 2.537（QW 的 2.55 附近），落在导模带之外，`eigs` 忠实返回了离它最近的**箱模阶梯**。
**处置**：移位点取 EIM 的 Re N(1)（或任何落在 Re n_b < N < Re n_a 内的值）；选模按**芯内功率占比**而不是按 Re 大小或模序。移位只决定"找到哪些"，不改变特征值本身 —— 这点要在报告里写明，否则会被当成循环论证。

### B7　二维 FD 的边界代价必须从判据里扣掉
**症状**：`h_e=0` 零号自检 FD 2.416485199 vs 一维 2.416918895，差 4.34e-4，看着像模型错。
**根因**：Dirichlet 侧壁的解析代价是 ΔN ≈ (π/L)²/(2k₀²N)，L=5 μm 时 4.2e-4 —— 与实测 4.34e-4 逐位吻合。
**处置**：判据写成 `|N_fd − (N_1d − ΔN)| < 2e-4`，把边界代价显式扣掉；否则为了"过判据"会去改本来没错的网格。

## C 类：工具与流程

### C4　主文件的局部函数，脚本调不到
**症状**：脚本里调 `e3_log` / `e3_phi_at` / `layer_bounds` 报「未定义函数」，`matlab -batch` 退出码 1。
**根因**：它们是 `Model_Self_L3_7L_EBL.m` 的局部函数，对外不可见。
**处置**：① 需要外部调用的一律走分发（`Model_Self_L3_7L_EBL('stage3', struct('sub',...))`，新增 `case 'check'` 就是为了让脚本能用 `e3_check`）；② 探针写成同目录的 function 文件、自己重算，别指望借用局部函数。

### C5　`run()` 会切 cwd；`global` + try/catch 会吞输出
**症状**：`run('Mode_L3/test_stage3/t4_field.m')` 之后脚本里 `addpath('Mode_L3')` 变成 `Mode_L3\Mode_L3`，fopen 相对路径全失败；探针里设了 `global E3_LOG_FID` 再包 try/catch，输出全被吞。
**处置**：脚本用 `fileparts(mfilename('fullpath'))` 定位自己的目录，不要假设 cwd；探针直接 `fprintf` 到控制台，别依赖 global 日志句柄。

## D 类：环境

### D5　MATLAB 的中文输出经管道必乱码，只读数字
**处置**：日志一律 `fopen(...,'w','n','UTF-8')`，用 read 工具或 `Get-Content -Encoding UTF8` 看；`pwsh` 里 `2>&1` 出来的 `[PASS]/[FAIL]` 只用来看数量与阈值，不看中文标签。`matlab -batch` 有未捕获错误时退出码 1，`run_all_stage3.m` 末尾按 `E3_NFAIL` 抛错把退出码置非零 —— 这是 A 类判据唯一可靠的出口。


## GUI 坑记录（2026-10-29）

`Mode_L3/l3_ui.m` 是 `uifigure` 单文件应用：三列（结构 / 层参数 / 三维预览）+ 成果画布 11 项，物理全部现算（经 `Model_Self_L3_7L_EBL('stage3', struct('sub','ui',...))`）。这一栏记做界面时踩的坑，编号 G 开头。

**和求解器那栏的区别**：界面这边的坑不产生错数，而是让「看到的东西」和「算出来的数」脱节、或者让用户的操作失效 —— 同样是"错得不响"，只是错在**观察链**上。

### G1　`uifigure` 在 `matlab -batch` / `-nodesktop` 下根本起不来
**症状**：`matlab -batch "f=uifigure"` 直接挂死、无输出；`-nodesktop` 报 `MATLABWindow 应用程序未能启动。Unable to launch the MATLABWindow application. The exit code was: -2147483645`（CEF 起不来，栈在 `matlab.internal.cef.webwindow`）；`New-Object -ComObject Matlab.Application` 报 `0x80080005 CO_E_SERVER_EXEC_FAILURE`。
**后果**：AI 侧无法自动打开界面自检，"排版对不对"只能靠人看图口述 —— 直到找到截屏方案（G21）。
**处置**：① 界面的自检一律走**经典 figure + 经典 axes**（同一套 `d_*` 画图函数接受任意 axes 句柄）；② 三维预览写 `probe_view.m`，用同一套几何/相机参数在经典 axes 里渲 PNG 自检。

### G2　`patch` 的默认高光把三维图打成一片白
**症状**：三维预览"彻底变白"，只看得见轮廓线，分层颜色全没了；同一份数据在经典 axes 里正常。
**根因**：`patch` 默认 `SpecularStrength = 0.9`、`DiffuseStrength = 0.6`，再叠加 `camlight headlight` + `lighting gouraud`，白边高光把淡色面冲成白。
**处置**：`lui_box` 统一 `'FaceLighting','none'`、棱边用中灰；`lighting(ax3d,'none')`，不要 `camlight`。这张图的用途是读层序，不是渲染 —— 平面色块比立体感重要。

### G3　每次重画都设 `view()` → 用户拖好的角度被顶回去（"转不动"）
**症状**：左键拖动能转，但一松手（触发重画）就跳回初始角度，用户结论是"不可以旋转"。
**根因**：`draw3d` 里无条件 `view(ax3d, S.yaw, S.pitch)`。
**处置**：`S.needview` 门闩 —— 只有初始化、复位、改几何时置 true；拖拽路径不碰视角，重画只重画内容。

### G4　`view(az,el)` 的上方向恒为 +z，做不出"层竖向堆叠 + 横向转出侧面"
**症状**：想要"快轴 y 朝上、层一层层往上摞"，给 `view(37.5,62)` 得到的却是 z 竖起来、层序横躺；把仰角调到 90（正对截面）后又发现左右拖只会绕屏幕法线原地打转、看不到侧面。
**根因**：`view(az,el)` 的相机 up 向量恒为 +z，这对参数表达不了"换 up"；`el=90` 恰好是万向锁点，此时改 `az` 只改变屏幕内的滚转。
**处置**：放弃 `view`，直接摆相机 —— `camup = R*[0;1;0]`、`campos = camtarget + R*[0;0;1]*dc`，`R = Ry(-25°)*Rx(-12°)`。up 的滚转分量不随拖动累积，转久了也不会歪。

### G5　相机必须最后摆：先摆相机、后改坐标范围 = 白摆
**症状**：加完 camup 后图仍躺倒；或第一次重画对、第二次又躺。
**根因**：相机与坐标范围互相牵制；`xlim/ylim/zlim` 一变，MATLAB 重算 `camva`/`campos`，把刚设的 camup 覆盖回 `[0 0 1]`。
**处置**：`draw3d` 里先 `view(ax3d,0,90)` 定 up 与距离（读一次 `S.dc = norm(campos-camtarget)`），**几何与范围全部改完之后**，末尾由 `apply_cam()` 统一摆相机。

### G6　`CameraPositionMode='manual'` 之后改 `pbaspect`，内容被推出画面
**症状**：整张空白，但 `XLim` 看着正常。
**根因**：相机模式全设 manual 后，`pbaspect` 改盒形时不再重算相机，视锥对不准内容。
**处置**：不要 manual 相机模式，用"最后摆相机"（G5）代替。

### G7　`CameraViewAngleMode='manual'` 会沿用上一次的小视角
**症状**：结构缩成一个看不见的点（或糊满屏）。
**根因**：manual 之后 `camva` 停在上一次的值（实测被压到 6.6°）。
**处置**：同上，交给 auto + 最后摆相机；确需固定视角时显式写 `camva`，不要只关 auto。

### G8　`XTick = []` 会把 `XLimMode` 悄悄改回 auto
**症状**：为把 x 轴数字挪到底面，先试 `XTick=[]` → 整张图缩成 [-1,1]、结构消失（连渲两次空白，一度以为是相机问题）。
**根因**：清空刻度会让坐标轴回到 auto，紧接着的 `plot3` 按新数据重算范围。
**处置**：只藏**数字**、不动刻度 —— `ax3d.XTickLabel = {}`，再在底面近棱外侧 `text(...,'Tag','uiaxlab')` 自绘数字（每次重画先按 Tag 删旧的）。`XTickLabel={}` 不影响范围。

### G9　三维 axes 上不能设 `XAxisLocation`；`XDir='reverse'` 是镜像不是移位
**症状**：`ax.XAxisLocation='bottom'` 直接报错；退而求其次 `XDir='reverse'` 之后 y 跑到右边、z 跑到底部，整个场景镜像。
**处置**：三维轴没有"轴位置"概念（只有二维有）。要挪就按 G8 自绘；`XDir` 只改数据方向，别拿来挪刻度。

### G10　用真实 L_z 当纵深，`DataAspectRatio` 会把相机推到很远
**症状**：正对截面时结构被压成一条细线，`CameraViewAngle` 只有 6.6°、`CameraPosition` 的 z 到 1.4e4。
**根因**：`L_z = 1500 μm` 对 `L_x = 10 μm`，比例变成 10 : 1 : 1560；MATLAB 为保证等比例，把相机拖到极远再压小视角。
**处置**：纵深用示意单位 `Zd = 0.25*max(Lx,1)`，真实 `L_z` 只写在 z 轴标签里（「示意；实际 L_z = 1500 μm」）。这张图不承担定量。

### G11　`colorbar` 挂在图窗上，`cla` 清不掉 → 每画一张叠一条色标
**症状**：二维远场那张图有**两套**色标刻度（一套 0–1、一套 −30–0 dB），越切越多。
**根因**：`colorbar` 的 parent 是 figure 而不是 axes 的 child，`cla(ax)` 清不到。
**处置**：`l3_draw` 开头 `delete(findall(fig,'Type','ColorBar'))`，顺手把 parent 为 figure 的游离 `text` 也删掉。

### G12　`cla` 不重置 `yyaxis`；`yyaxis` 有"当前作用侧"
**症状**：第 2 项图上多出一条看不懂的橙色曲线（其实是第 1 项的右轴折射率残留）；另一处 `text` 写完后一个字都看不见。
**根因**：① `cla` 保留双轴结构，上一张的右轴数据还在；② `yyaxis(ax,'right')` 之后"当前作用侧"是右轴，随后 `text(ax,x,y,...)` 的 y 按右轴量程（1.7–2.6）解释，整行字被扔到轴外。
**处置**：清图用 `cla(ax,'reset')`（连双轴状态一起清）；画完右轴数据后显式 `yyaxis(ax,'left')` 再写左轴相关的文字。

### G13　主入口的 `clc; close all` 会把别人的图窗一起关掉
**症状**：界面里点"成果"按钮后界面窗口自己消失；或前一页的图被下一次求解清空。
**根因**：模型主入口开头有 `clc; close all`，界面每次调模型都执行一遍。
**处置**：加 `keep_windows` 守卫（`opt.keep_windows` 为真时跳过），界面与自检调用时带上；原行以 `% ##` 保留原文。

### G14　重建状态时漏掉"运行时字段" → 图窗回调抛错
**症状**：`无法识别的字段名称 "camDrag"`，出错在 `on_motion`，鼠标一动就刷屏。
**根因**：`on_clear` 里 `S = lui_default();` 整体替换状态，而拖动/相机这批字段是主函数额外补的，替换后全没了；图窗级 `WindowButtonMotionFcn` 仍在调 `on_motion`。
**处置**：新增 `lui_live(S)` 集中补这批字段，初始化与清空都走它 —— 以后加新字段只改一处。

### G15　嵌套函数里不能再定义函数
**症状**：`check_state` 里定义 `setfail` 报错。
**处置**：收集 `bad{}` 列表，最后 `strjoin(bad,'；')`。

### G16　`struct('name',{...})` 里的 `{...}` 是空 cell
**症状**：`it(1).name = ...` 报「不支持使用 '=' 运算符」。
**处置**：空结构体数组写成 `struct('name',{},'file',{},'desc',{})`。

### G17　UI 字形三坑：`⚙` 变方框、连续空格被折叠、`Consolas` 无中文
**症状**：按钮写 `⚙ 高级设置`，齿轮显示成方框；层表 `tag    d=...` 的空格被压成一个；成果页右列中文全变方块。
**处置**：① UI 不用 emoji/特殊符号；② 定宽对齐用 `%-6s` 而不是手打空格；③ 中英混排用中文字体，`Consolas` 只给纯 ASCII 列。

### G18　`Button` 没有 `ButtonDownFcn`，拖动排序只能图窗级做命中测试
**症状**：想给层表每行加"按住拖动排序"，`uibutton` 只有 `ButtonPushedFcn`（`meta.class` 查证），没有按下事件。
**处置**：图窗级 `WindowButtonDownFcn/MotionFcn/UpFcn` + `pos_in_fig(h)` 逐级累加 Position 得图窗坐标 → 命中行 → 拖动超过 12 px 才算移动 → 落点行夹在 `[2, N-1]`（顶层与衬底不可动）。副作用：没有"跟随的幽灵行"，观感一般。

### G19　界面里的缺省数不能凭印象写
**症状**：界面算出的 α = 21.1 cm⁻¹，模型是 5.89 —— 差 3.58 倍。
**根因**：七层逐层 α 是凭印象填的（4.20/5.02/90.79/…），真值来自 `stage2_alpha_table`：`[0, 1.173209, 1.401295, 25.352696, 10.034002, 17.790425, 26.685638]`。
**处置**：界面缺省结构**从模型取**（`S(1).alpha`），并在自检里与 T3 逐位对齐（现在 `l3_ui('selftest')` 与 T3 逐位一致）。任何"手抄常量"都要有一条断言盯着。

### G20　"看得到的"和"算出来的"要能对上账
**症状**：二维模场图上看不出场被 `|x| < w/2` 夹住；图 1 的 QW 只有 4 px（9 nm 对 1.7 μm 的线性厚度）。
**处置**：① 三维预览竖直方向按 √(厚度) 压缩并给薄层最小高度兜底；② 关键几何（脊边、QW 上下沿）在图上画参考线；③ 图注写明"竖轴按 √(厚度) 压缩"，否则读者会去量比例。

### G21　AI 侧自检只能靠截屏：DPI 感知是前提
**症状**：`Screen.AllScreens` 报 1707×1067，而实际屏幕 2560×1600（150% 缩放按 2/3 报）。
**处置**：`[Wsh]::SetProcessDpiAwarenessContext([IntPtr](-4))`（失败退 `SetProcessDPIAware()`）再 `CopyFromScreen`；截之前先 `ShowWindow(SW_RESTORE)` + `SetForegroundWindow` + 等 500 ms + 重读 `GetWindowRect`（钳到屏幕内），否则截到的是被遮挡的旧画面。

### G22　用脚本改代码文件的两个坑
**症状**：`edit` 在含中文/希腊字母的行上频繁 `old_string was not found`；`python -c` 拼 MATLAB 单引号时 `'reset'` 变成 `reset`；splice 后报 `无法识别的 'endfunction'`。
**根因**：① 编码/规范化差异；② bash 把 `''` 折叠掉；③ 拼接的新函数文本末尾少了回车。
**处置**：① 含非 ASCII 的改动写 python 补丁脚本，按锚点整段替换、`io.open(...,'w',encoding='utf-8',newline='\n')` 写回；② python 里的单引号用 `chr(39)`；③ splice 后 `grep -c '^function'` 确认无重复定义、`tail -c 40` 确认末尾有换行。

### G23　两处"一次就踩"的 MATLAB 约束
- 函数名**不能以下划线开头**（`_chk.m` 报「文本字符无效」）。
- R2023b 的 `checkcode(...,'-struct')` **没有 `isBenign` 字段**，遍历时只能用 `c(k).line` / `c(k).message` 自己数。

### G24　相机"设了但没生效"：调用点漏了 + 布局时被 auto 重算
**症状**：默认视角一直是"整个截面正对用户"（没有立体感），但拖动一下就有角度 —— 说明姿态计算是对的，只是初始那一次没摆。
**根因**：① `draw3d` 里算出了 `doCam` 却没有一处调用 `apply_cam()`（唯一的调用点在 `on_motion` 里），所以首帧停在 `view(0,90)`；② 补上调用后仍有隐患：`campos/camup` 的 Mode 还是 auto，uifigure 布局完成（或拉窗口）时 MATLAB 按 az/el 重算 campos，把 up 覆盖回 `[0 0 1]`。
**处置**：`draw3d` 末尾 `if doCam, apply_cam(); end`；`apply_cam` 里在设置之后把 `CameraPositionMode/CameraTargetMode/CameraUpVectorMode` 置 manual（必须在坐标范围与 `pbaspect` 定稿之后，否则重现 G6）。
**教训**：凡是"算了一堆标志位"的绘制代码，检查每个标志位是否**真的被消费**；这类漏调用不会报错，只表现为"某一帧是默认样子"。
