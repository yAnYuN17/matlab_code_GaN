# 阶段 2 坑记录增量

只记"不报错、但给错数"的坑。格式：现象 → 根因 → 修法 → 怎么防。
编号接阶段 1（A–G），本阶段用 H。

---

## H1 用子集下标索引全表 struct，表格错行但数字看着都对

**现象**：S7 通道表里 p-wave 的载流子浓度打印成 2e19（应为 1e19）、p-clad 打印成 2e19（应为 3e19）；
但同一行的 α 值完全正确（p-clad 26.686 = 3e19 × 0.889e-18）。数字自洽，只有 N 列是别人的。

**根因**：`stage2_s7_alpha_table` 返回的是 10 层全表（含 QW1/barrier/QW2），
而 7 层结构的 `tags` 只有 7 个、且中间跳过了三个层。
打印循环用 `tab(j)`，j 是 7 层子集的下标，于是从第 5 行起整体错位。

**修法**：按层名回查下标 `kt = find(strcmp({tab.tag}, tags{j}), 1)`，取 `tab(kt).N`。

**怎么防**：任何"表 A 的下标 ↔ 表 B 的下标"的对应，都用名字查，不用位置。
位置对应只在两张表的元素个数与顺序**逐条相等**时才成立，而这一点往往没有被断言。

## H2 判据选了会被舍入放大的把手，把 0.5% 的吻合读成 17% 的偏差

**现象**：用 Kioupakis Table I 参数化反查 Table II（520 nm），
p-clad 的 α 相对偏差 0.5%、n-clad 却 17.3%。看起来"小 Γα 的行模型不对"。

**根因**：Table II 只印到 0.1 cm⁻¹，n-clad 的 Γα = 0.2，末位一个舍入就有 ±0.05，
折回 α 就是 ±25%。用 α 的相对偏差当判据，等于用被舍入放大的量做分母。

**修法**：判据改成直接比 Γα：`|ΔΓα| ≤ 0.06`（半个末位），QW 行单列、不参与判据。
（2026-10-22 更新：QW 行单列的理由本身后来被推翻了——它差的 1.8 倍是漏了电子通道，
见 H10。现在六行都参与判据。）
改后 p-clad 0.05、p-guiding 0.05、EBL 0.03、n-guiding 0.03、n-clad 0.03，全部落在舍入内。

**怎么防**：写判据前先问"这个量的最后一位是多少、它决定的最小可分辨差是多少"。
相对偏差只在该量的有效位数足够时才用。

## H3 "窗口内无根"被读成"模消失了"

**现象**：衬底折射率扫描里 n_sub ≥ 2.418 之后 Re(n_eff) 全是 NaN，
图上看像"泄漏模在 2.417 截止"。

**根因**：束缚模求解器的搜索下界是 `n_lo = max(n_sub, n_clad) + 1e-9`。
n_sub 一旦超过 Re(n_eff)，真正的根就落在这个窗口之外——**窗口把根排除了**，不是根不存在。
此时模已经变成泄漏模（复根、有衰减），要用 PML 或复平面分支才能求。

**修法**：报告里把阈值写成"束缚模求解器最后一个有根的 n_sub = 2.416"，
并在图与正文两处写明红带 ≠ 模消失；泄漏模求解留阶段 3。

**怎么防**：任何"找不到根"先做三件事——打印窗口端点、打印端点处的 |f|、把根的位置和端点比一比。
"求解器失败"与"物理上没有解"是两件事，前者可以用工具属性解释，后者要物理判据。

## H4 把复根只取实部代回色散函数，判成"参考解不是根"

**现象**：核查 S6 第二段的解析参考解是否可信时，写了个探针：把 `Re(n_eff)` 代进 TMM 色散函数，
得到归一化残差 |f|/max = 0.535、邻域比 ratio = 1.036（>0.5 门限），
于是判"解析参考解不是根、该段实验作废"。**这个判断是错的。**

**根因**：根是复数（α = 1e4 时 Im n_eff = 0.036），探针里只用了打印出来的实部，
代入点离真正的根有 0.036 的虚部距离，残差当然降不下去。
S6 表里打印的是 `Re(n_tmm)`，只有 `%.9f`，虚部根本没出现在屏幕上。

**修法**：直接用结构体里的复数字段核对——`table2(k).ne_t` 与 `table2(k).ne_a`：
α = 100 / 3000 时实部虚部**逐位相同**，α = 1000 时末位差 1e-15 ⇒ 参考解确实是根，该段有效。

**怎么防**：任何"把根代回去算残差"的检查，先确认代进去的是**完整的复数**，不是打印出来的实部。
屏幕上看到的小数位数不等于变量的精度；判据的输入必须来自变量本身，不能来自显示格式。

## H5 改了全局 α 表却没有重建层结构，α_mode 恒为 0

**现象**：S5 微扰标尺第一版跑出来所有算例的 α_mode 都是 0，但 P_layer 正常、根也正常。

**根因**：α 是在 `stack_7layer` 里一次性写进 `n` 的；改 `STAGE2_ALPHA` 全局表之后没有重新调用
`stack_7layer`，层结构还是上一轮的（空表 ⇒ 全 0 虚部）。

**修法**：每轮改完 `STAGE2_ALPHA` 都重新 `L = stack_7layer(lambda)` 并重建 `fh`。

**怎么防**：全局状态（global 表、缓存）与派生对象（层结构、函数句柄）之间要有明确的"重建点"，
并且第一件事就是打印一个能暴露"全 0"的量（这里是 α_mode）。

## H6 主函数没声明 global，α 静默变 0（数字有限、程序不报错）

**现象**：A 步第一次跑，表一 α_i 三个模全是 0.000，而同一段代码打印的层分解 ΣP·α = 6.167、
α 表里 p-clad 是 26.686。两组数互相矛盾，但没有任何报错。

**根因**：α 走的是全局表 `STAGE2_ALPHA`。`alpha_of_layer`、`stage2_s7_channels` 等函数里
都写了 `global STAGE2_ALPHA`，**主函数里没写**。于是主函数里的 `STAGE2_ALPHA = Mx`
只是建了一个同名局部变量，真正的全局表一直是空的，层折射率虚部全 0。

**修法**：主函数开头补 `global STAGE2_ALPHA`（与其它函数同一行注释）。

**怎么防**：MATLAB 的 global 是**逐函数**生效的，`global` 少写一处不会报错、不会警告，
只会让赋值落进局部变量。凡是"写全局表 → 另一函数读"的路径，set 端与 read 端都要显式声明；
判据上要有一个能暴露"全 0"的独立量（这里是 ΣP·α 与 α_i 的对比，6.167 vs 0.000）。

## H7 struct('tag', {cell}) 把 1 个 cell 展开成 1×N 的结构体数组

**现象**：`stage2_solve_api` 第一次跑报 `MATLAB:scalarStrucRequired`——"该赋值需要标量结构体"。

**根因**：`struct('tag', {Lx.tag}, ...)` 里 `{Lx.tag}` 是 1×1 的 cell，但 struct 会把 cell
**按元素展开**：N 个层名 ⇒ 1×N 的结构体数组。循环里 `S(j) = one` 时 one 不是标量，报错。

**修法**：要存 cell 本身就得再包一层：`'tag', {{Lx.tag}}`。

**怎么防**：凡是用 struct(...) 装 cell / 数组，先 `size(struct(...))` 看一眼；
1×N 的"标量结构体"错误，几乎都是这里展开出来的（与 D1 的 struct 数组展开同源）。

## H8 层名带 '-' 不能做 struct 字段名，α 表要用 containers.Map

**现象**：把逐层 α 表写成 `struct('n-clad', 3)` 或 `st.('n-clad') = 3`，
MATLAB 报"字段名无效: 'n-clad'"。

**根因**：MATLAB 字段名必须是合法标识符，'-' 不是。项目里的层名（n-clad、n-wave、p-clad…）
天然带连字符，所以 α 表从一开始就用 containers.Map（见 `alpha_of_layer` 的注释）。

**修法**：检验脚本要传逐层 α 时用 `M = containers.Map(); M('n-clad') = 3;`，
再 `Model_Self_L2_7L_EBL('solve', struct('alpha', M))`；'solve' 接口同时接受 struct 与 Map。

**怎么防**：不要把"人读的层名"直接当字段名用；需要结构化时先问这个名字是不是合法标识符。

## H9 求根失败时接口返回 0×0 空结构，调用方一取 S(1) 就报越界

**现象**：`test_s7_channels` 的衬底扫描走到 `nsub = 2.42`（窗口内无根），
下一行 `if S(1).ok` 直接报"索引超出数组元素的数目 (0)"，
报错信息指向取下标那一行，完全看不出真正原因是"这个折射率下没有解"。

**根因**：`stage2_solve_api` 原来是"有几根就返回几个元素"，无根时
`S = struct('ne', {}, ...)` 就是 0×0 空结构体数组。
调用方习惯性按"成功路径"写 `S(1)`，于是崩在取下标，而不是崩在"无解"这个语义上。
同一接口在不同算例下返回不同长度的数组，调用方就得每次先判 `isempty`，忘一次就报错。

**修法**：`stage2_solve_api` 在 `isempty(Sx)` 时返回 `n_modes` 个占位元素：
`ne = complex(NaN, NaN)`、`Gamma/P_layer/contrib = NaN`、`ok = false`、`alpha/ch/tag` 照填。
接口契约写进函数头：**S 的长度恒为 n_modes，ok=false 表示这个模没解出来，数值字段为 NaN**。
扫描类代码于是只判 `S(1).ok`，不必再判空。

**怎么防**：设计"可能失败"的返回接口时，先把失败时的形状定死（空？NaN 占位？抛异常？），
再写调用方。最怕的是"长度随算例变"的静默约定——它把语义错误伪装成下标越界。

## H10 一行对不上就把它"单列不判"，掩盖了真正的原因（QW 少了电子通道）

**现象**：用原文 Table II 反查 Table I 系数时，六行里五行 |ΔΓα| ≤ 0.05，
只有 QW 行差 1.8 倍（预测 α = 49.14，原文 Γα/Γ 反推 90.0）。
当时的处理是"QW 行单列、不参与判据"，理由写成"量子阱子带/偏振/Γ 定义可能不同，未查证"。

**根因**：QW 行只取了空穴截面 σ_h，而量子阱里电子和空穴都在（各 2×10¹⁹ cm⁻³）。
加上电子通道 σ_e 后 α = 2e19×(2.457e-18 + 2.062e-18) = 90.38 cm⁻¹，
Γα = 2.711 vs 原文 2.7，差 0.011。系数没错、模型没错，是**输入假设漏了一项**。

**修法**：`test_s7_selftest` 的 QW 行改成载流子 `'he'`（两种各 N），六行全部参与判据；
判据仍是 |ΔΓα| ≤ 0.06，实测 max = 0.051（QW 行 0.011）。

**怎么防**：
1. 一行偏差落在 1.5–2.5 倍这种"整数级"区间时，先怀疑**漏了一个通道/一项贡献**，
   而不是先怀疑"这层物理不一样"——漏项常常正好是 1.5–2 倍。
2. "单列不判"是权宜，不是结论。写进文档时必须带"未解释"三个字，并且它应该一直刺眼，
   直到被解释或被证伪；这次它从 S7 一直挂到 S9 之后才被翻出来。
3. 判据要能反过来提示原因：六行里只有一行偏、且偏的方向一致（都偏小），
   这个模式本身就指向"少加了一项"，而不是随机误差。

## H11 sprintf 里的 `\alpha` 被吃成响铃字符，标题显示成"□lpha_i"

**现象**：3D 面板的标题印成 `TE0  KIO  □lpha_i = 6.182 cm^{-1}`，方块里是 ASCII 7（响铃）。
同一张图的 zlabel 却是正常的 α。

**根因**：`sprintf` 会把 `\a` 当转义序列（bell）。标题用 `sprintf('... \alpha_i ...')`，
文件里只写了一个反斜杠；zlabel 是普通 char 向量（不经 sprintf），所以单个反斜杠没事。

**修法**：sprintf 字符串里写**两个**反斜杠（文件内容为 `\\alpha`），或在外面先拼好再 `title(ax, s)`。

**怎么防**：凡是在 `sprintf` 里放 TeX 记号（`\alpha`、`\beta`、`\mu`、`\times`），
一律先在命令行试一次 `sprintf('\alpha')` 看长度是不是 1——长度 1 就是被转义了。
单位里的 `cm^{-1}` 不受影响（`^-` 不是转义），所以错误只出现在希腊字母上，容易漏看。

## H12 uitable 的可用宽度要先扣行号列，余量也不能全塞给最后一列

**现象**：表一底部出现横向滚动条（内容明明不宽）；第一版修法之后滚动条没了，
但 `norm check` 列被撑到约 600 px，左边 `n_eff` 被截成 `2.417128…`。

**根因**：两件事叠在一起。
1. uitable 左侧的行号列（`#`）不在 `ColumnWidth` 里，却占约 46 px。按 `Position(3)` 算列宽时不扣它，
   总宽就超出，于是出滚动条。
2. 第一版把"总宽 − 各列需求"的余量整个加给最后一列。需求小的列分不到，需求大的列过肥；
   而 `uistyle`/`ColumnWidth` 的单位是像素近似值，最后一列吃下几百像素就会把别的列挤到截断。

**修法**：`col_widths` 先按内容估每列需求（`Lk*0.72*fs + 18`，下限 50 px），
再用 `avail/sum(need)` **等比**缩放铺满；舍入误差给第一列。调用方传 `avail = 窗口宽 − 46`。

**怎么防**：
1. 任何"按像素分配宽度"的控件，先量出**不可见/不可控部分**（行号列、滚动条、边框）再从总量里扣。
2. 余量不要全塞给某一个元素。等比缩放能让"截断"均匀发生在所有列上，一眼就能看出是宽度不够，
   而不是某一列被撑胖。
3. 改完必须截图看——这类问题在代码里完全合法，只在渲染时露馅。

## H13 patch 只画三个面，缺的棱让长方体像"没关上的抽屉"

**现象**：三维层分解图里每块长方体看着像"开放的抽屉"——背面那条竖棱没有线，视觉上立方体没闭合。
数字全对，只是图看着别扭。

**根因**：`box3` 只给 `patch` 传了 +x、+y、顶三个面。`patch` 的 `EdgeColor` 只描**它自己那些面**的边框，
于是没画的面上的棱就缺线。看上去像漏画，其实是"面"与"棱"两套图元没对齐。

**修法**：五个面（仍不画朝下的底面，避免与下一块顶面共面打架）+ 十二条棱逐条 `plot3`；
远处的棱由深度缓冲遮挡，不需要手工剔除。实测 view(-40,24) 下轮廓完整。

**怎么防**：用 `patch` 拼立体时，"面数"不等于"棱数"。要么画满六个面（让 `patch` 自己描全边），
要么面画一部分、棱单独补齐；只靠部分面的 `EdgeColor` 一定会缺边。
看图时留意"闭合感"——缺一条棱比缺一整面更容易被当成"风格"放过去。
