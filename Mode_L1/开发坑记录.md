# A 类：静默给出错误结果（★★★）

## A1. 根搜索截断方向反了 —— 基模被高阶模挤掉

**代码位置**：`src/find_roots_complex.m`（去重与截断段）

**现象**：
解析路径与 TMM 路径的**模数完全一致**，但 n_eff 系统性错位：
```
analytic: m=0 → 3.493421   m=1 → 3.473834   m=2 → 3.441925
tmm     : m=0 → 3.473834   m=1 → 3.441925   m=2 → 3.401800
```
analytical 的 `m=1` 恰好等于 TMM 的 `m=0`，像是"整体平移了一位"。
这正是最容易被误判成"某条路径的模序定义不同"而放过去的形态。

**根因**：
该结构在搜索区间内实际有 **4 个**根，而 `n_modes = 3`。
原代码 `roots_n = sort(roots_n); roots_n = roots_n(1:n_roots);` —— **升序**排序后取前 3 个，
留下的是 **n_eff 最小**的三个，即最靠近截止的高阶模，**基模被直接丢掉**。

**物理判断**：波导问题里 **n_eff 越大 ⇒ 模序越低 ⇒ 物理上越重要**（基模的 n_eff 最大）。
保留"最小的几个"等于专门扔掉最关心的那些。

**修法**：改为降序，保留**最大**的 `n_roots` 个；并已补 `n_modes + 2` 的余量再截断。

**怎么防**：
- 任何"取前 N 个"的截断，先问一句**排序方向与物理重要性是否一致**。
- 交叉验证时，**模数一致不等于结果正确**——必须逐个比 n_eff 的数值。
- 这条已经写进 `find_roots_complex.m` 的注释里，不要删。

## A2. 截止判据用 `f(n_high + δ)` 的符号 —— 引入 2×10⁻⁴ 的假偏差

**代码位置**：`src/solve_analytic3.m`（截止判据段）／曾影响 `tests/t02`、`tests/t03`

**现象**：
A3 / A4 的截止核对**卡在 1e-4 量级过不去**：
```
m=0  数值 V_c = 0.778231   解析 V_c = 0.778045   相对偏差 2.39e-04
m=1  数值 V_c = 3.919823   解析 V_c = 3.919638   相对偏差 4.74e-05
```
规律很明确：**偏差随 m 增大而减小**，且数值总是**偏大**。
看起来非常像"求解器精度不够" → 会引导人去调二分容差、加密扫描，**方向完全错了**。

**根因**：
判据写成了"`real(f(n_high + δ)) > 0` 则第 m 阶存在"，其中 δ = 1e-9·n_core。
但色散函数在 `n_high + δ` 处与极限值 `g = lim_{n_eff→n_high⁺} f` 相差
```
arctan(γ(δ)/κ) ≈ k0·√(2·n_high·δ)/κ ≈ 2e-4
```
这个偏移被**直接加到了截止点上**。m 越大，`κ_max·d` 越大而偏移不变，
所以相对偏差随 m 减小 —— 观测到的规律完全对得上。

**修法**：改用**解析极限值**做判据
```
TE : g_m = κ_max·d − arctan(γ_low/κ_max) − mπ
TM : g_m = κ_max·d − arctan((n_core/n_low)²·γ_low/κ_max) − mπ
其中 κ_max = k0√(n_core²−n_high²)，γ_low = k0√(n_high²−n_low²)
```
（TE 情形等价于经典的 V > arctan(√a) + mπ。）
修正后偏差降到 **1e-12**（t02）与 **3e-14**（t03）。

**修的过程中又踩了第二层坑**：
改完之后我在那里加了一条 `error` 断言"精确判据说存在但二分下界处函数已为负就报错"。
结果**误触发**了：当 `g` 本身只有 1e-5 量级（模刚过截止）时，
`f(n_high+δ) − g ≈ 2e-4` **盖过了 g 本身**，断言必然报错。
最终改为：**用极限值 `g` 作为二分区间的左端点**，并允许根自然贴到 `n_high` 上
（此时绝对误差 < δ，相对误差 < 1e-13，对任何下游用途都足够）。

**怎么防**：
- 凡是"在极限点附近取函数值代替极限"的写法，先估一下**偏移量的量级**。
- **偏差随参数呈规律变化**，几乎总是"系统性偏置"而非"随机误差"。
  如果偏差随 m 单调减小，先怀疑判据，不要怀疑容差。
- 加断言时要想清楚：**断言的条件是否在所有合法输入下都成立**。这次的断言只在
  `g >> δ` 时成立，写的时候没意识到 `g` 可以任意小。

## A3. Γ 无定义时返回 0 而不是 NaN

**代码位置**：`src/confinement_factor.m`

**现象**：结构里没有任何层标记 `is_active` 时，Γ 返回 0，
下游读到的信息是"**模式与有源区完全不重叠**"——这是一个**看起来合法的物理结论**。

**根因**：把"输入有问题"和"物理结果是零"两种情况用同一个数字表达了。

**修法**：
```matlab
if ~any(act)
    G = NaN;   % 而不是 0
    ...
end
```
NaN 在任何后续运算中都会显式传播，逼使用者面对"结构没标有源区"这个**输入问题**。
另外去掉了 `warning`：solve_slab 对每个模都调用一次，警告会刷屏反而被忽略。

**怎么防**：区分"物理量真的是 0"与"物理量无定义"。后者一律用 NaN。

## A4. 两条"独立"路径可能是伪独立

**不是代码 bug，是验证方案的设计缺陷**，但后果最严重，所以放在这一类。

**风险**：路径 1（解析超越方程）与路径 2（TMM）虽然数学路径不同，
但都由同一套"分层 + 界面连续 → 色散方程"的推导而来。
**若推导本身写错**（例如 TM 的界面条件写成 TE 的、或衰减解取了增长分支），
两条路径会**一起错**，A1/A2 双双通过而结论是错的。

**这就是"自证"漏洞**：交接报告里 A1 要求"三层 n_eff 与解析解吻合 1e-6"，
但**解析解本身也是数值求根得来的**，不能给自己当标尺。

**修法**（本阶段实际做了两件事）：
1. `tests/t00_symbolic_check.m`：用 Symbolic Math Toolbox 从 Maxwell 方程 +
   界面连续条件**重新推导**色散方程，与代码里手写的逐项比对（结果：差为 0）。
   注意必须**从物理出发重推**，而不是把代码里的公式抄一遍给符号运算——那样等于没验。
2. `src/solve_fdm.m`：**把 Helmholtz 方程直接离散成矩阵本征值问题**，
   连"色散方程"这个中间产物都不要。它与路径 1/2 不共享任何一行推导。

**怎么防**：验证方案设计时问一句——**"这些路径是否共享同一个可能出错的前提？"**
若共享，必须再加一条从更底层出发的路径。

## A5. `trapz` 跨越不连续的 mask —— Γ 被抬大约 2 倍

**代码位置**：`src/confinement_factor.m`（有源区功率积分段）
**发现场景**：把单层等效 QW 展开成 阱-垒-阱（7 层 → 9 层）时暴露。

**现象**：
双层阱结构（3 nm 阱 / 6 nm 垒 / 3 nm 阱）解出的 Γ 与各层功率占比对不上：

```
Γ                          = 0.03408936
P_layer(QW1) + P_layer(QW2) = 0.0170407      ← 差了约 2 倍
```

而单层 QW 的 7 层结构两个数完全相等（都是 0.02677501）。
也就是说：**同一个 Γ 定义，在单层结构下正确，在多层结构下翻倍。**

**根因**：
原文是
```matlab
mask   = false(size(y));
for k = 1:N
    if L(k).is_active
        mask = mask | (y >= yb(k,1) & y <= yb(k,2));
    end
end
P_act = trapz(y(mask), w(mask));      % ✗
```
当 `is_active` 的层**不连续**时（阱与阱之间隔着垒），`y(mask)` 把几段
**拼接**成一个连续数组。`trapz` 只认数组，不认间隙，于是在上一段的末点与
下一段的首点之间拉了一条直线——**把中间的势垒整段积了进去**。

量级核对：多算的那块梯形 ≈ 垒厚 6 nm × 垒内平均 |φ|²，
与阱自身的积分恰好同量级，所以误差表现为"约 2 倍"而非一个小修正。

**为什么之前查不出来**：
1. 单层 QW 时 `mask` 连续，`trapz` 行为正确，**这个 bug 完全不存在**。
2. 三条路径互验查的是 **n_eff**，而 Γ 是后处理——**路径交叉验证对此完全无效**。
   这是 A4 之外的另一个盲区：验证要覆盖**每一个物理量**，不只是本征值。
3. 它不报错、不警告，Γ = 0.0341 本身是个合法数字（0 ≤ Γ ≤ 1）。

**修法**：改为**逐层单独积分再求和**，天然按层分段，不跨越任何间隙：
```matlab
P_act = 0;
for k = 1:N
    if ~L(k).is_active, continue; end
    mk = (y >= yb(k,1) & y <= yb(k,2));   % 首尾半无限层另有分支
    if any(mk)
        P_act = P_act + trapz(y(mk), w(mk));
    end
end
```
修后 Γ 与 `sum(P_layer(is_active))` 严格相等（diff = 0），
且单层 QW 的结果**一字未变**（0.02677501，回归通过）。

**怎么防**：
- **凡是"挑出某些索引再积分/求和"的写法，先问一句：这些索引连续吗？**
  不连续就必须分段处理。`trapz` / `cumtrapz` / `diff` 都有这个陷阱。
- 给每个物理量配一条**独立的自洽检查**。这里用得上的是
  "Γ 必须等于各 `is_active` 层 `P_layer` 之和"——它把两个独立算出来的
  数钉在一起，2 倍偏差一眼可见。已写进 `Mode_L1_V1.0/README.md` §5.5「改完必须查的四项」。
- 层数一变就要重跑这条检查：**单层能过不代表多层能过**。

## A6. 函数收了 `pol` 却从不使用 —— TM 静默返回 TE

**代码位置**：`src/solve_fdm.m`（函数签名与函数体）
**发现**：2026-09-26 统筹会话核查时查出，2026-10-16 复跑 `crosscheck_v1_layers` 复现。

**现象**：
`solver='fdm'` 配 `pol='TM'` 时，返回结果与 `pol='TE'` **逐位相同**：

```
fdm TE = 3.493280527698  3.473254411654  3.440568315963
fdm TM = 3.493280527698  3.473254411654  3.440568315963   ← 逐位相同
tmm TE = 3.493280530768  ...
tmm TM = 3.493110306428  ...                             ← TM 与 TE 差 ~1.7e-4
max|fdm"TM" − tmm"TE"| = 2.79e-08   ⇒ fdm 的 "TM" 算的就是 TE
```

在 7 层真实结构上差得更大：`tmm` 与 `fdm` 的 TM 相对偏差 **5.77e-04**。

**根因**：`pol` **只出现在第 1 行（函数签名）与第 4 行（文档行）**，函数体内零次使用。
它的离散矩阵用的是 TE 的 Helmholtz 形式

```
d²E/dy² + k0²[n²(y) − n_eff²]·E = 0
```

而 TM 应当是

```
d/dy[ (1/n²)·dH_y/dy ] + k0²[1 − n_eff²/n²]·H_y = 0
```

两者的离散算子不同（TM 需 `1/n²` 的界面加权与 n 的导数项）。
照抄 TE 的算子去算 TM，**不报错、不警告**。

**这是一个"参数没接线"的形态**，与既有五条坑都不同：不是算法错、不是判据错、
不是数值陷阱，而是**入口参数在半路上断了**。对照 `solve_slab.m` —— 它把 `pol`
一路传下去（→tmm、→fdm、→模场/归一化/Γ），**同一条参数线，tmm 那头接上了，fdm 这头断了。**

**影响范围**：

- **当前影响 = 0**：A1–A7 全部只测 TE，生产路径是 tmm，且单文件模型不含 fdm。
- 唯一涉及 TM 的 `tests/t04_normalization.m` 走的是 `solve_slab` 的**默认 tmm 路径**
  ⇒ **本 bug 从未被任何测试覆盖**。
- ⚠ **危险场景**：后续若用 fdm 交叉验证 TM 的 tmm，会看到 ~5e-4 的偏差。
  **那不是 tmm 错，是 fdm 错**；若据此去"修" tmm，**会把对的改成错的**。
  这与 A4「两条'独立'路径可能是伪独立」同类，但更隐蔽 —— 这次连"路径独立"都不成立。

**修法（未实施）**：把 fdm 的离散算子按 `pol` 分支。
⚠ 需要 `1/n²` 的**界面加权**（不是简单地把 n² 换成 1/n²），
并注意 `Es(:,j) = real(v)/...` 的实部提取在 TM 下是否仍合适。

**怎么防**：

- **凡是"函数签名里有、函数体里没用"的参数，都要当嫌疑。**
  一行 `grep -n "<参数名>" file.m` 就能查 —— 命中数只有签名与文档行时，就是它。
- 测试要**覆盖参数的每个取值**：只测 TE，等于没测 `pol` 这个参数。
- 给求解器加一条**冒烟断言**：`pol='TM'` 与 `pol='TE'` 的结果必须不同（差 > 1e-6），
  否则说明 `pol` 被忽略了。`crosscheck_v1_layers` 的 P8 已有这一条。

## A7. 模序标签 off-by-one —— 表二列名与远场图例

**代码位置**：`Mode_L1_V1.0/Model_Self_L1_7L_EBL.m` 的表二 `lCols` 与图2 图例
**发现**：2026-10-16 用户看表、看图时先后发现（**两处都不是测试的覆盖范围**）

**现象**：

```
表二列名：P(TE-1) [%]   P(TE0) [%]   P(TE1) [%]     ← 列下装的是 TE0/TE1/TE2 的数据
图2 图例：TE1 / TE2 / TE3                            ← 实为 TE0/TE1/TE2
```

表一的 mode 列、主图图例都是对的，所以**同一个窗口里两处编号互相打架**。

**根因**：**模序从 0 起**（`modes(1)` 是基模 TE0），而循环下标从 **1** 起。
凡是 `sprintf('%s%d', pol, k)` 这种写法都会差 1，正确写法是 `k-1`。

表二那处更隐蔽：循环变量是 `j` 且从 **0** 起（`arrayfun(..., 0:numel(modes)-1)`），
里面又写了 `j-1` —— **两次偏移叠加，结果是 −1 / 0 / 1**。

**为什么测试兜不住**：A1–A7 全是**数值判据**（n_eff、Γ、正交性……），
标签是给人读的文字，**不在任何判据的覆盖范围内**。这类错误不报错、不改数，只让人读错表、
把 TE1 的 Γ 当成 TE2 的。

**修法**：统一用 `k-1`；把 `0:numel(modes)-1` 改成 `1:numel(modes)`。

**怎么防**：

- **全文件搜 `%s%d`，逐处核对编号基准** —— 本项目共 6 处，改完的对应关系：
  ```
  :116  modes(j).order  ✓ 基模自检        :236  k-1          ✓ 表一 mode 列
  :140  modes(j).order  ✓ 命令行远场      :250  j-1 (1:n)    ✓ 表二 P 列名
  :194  k-1             ✓ 图2 图例        :1092 k-1          ✓ 主图图例
  ```
- 更根本的办法：**编号只在一处生成**（比如统一走 `modes(k).order`），不要在每处重算。
- 新增任何"标签"时，把它和相邻的另一处标签**并排打印一次**对照（表一 vs 表二、图例 vs 表）。

# B 类：会报错但难定位（★★）

## B1. `eigs` 的选项名不是想当然的

**现象**：`eigs(A, k, 'largestreal')` 报错。合法值是：
`'lm' 'sm' 'la' 'sa' 'be' 'lr' 'sr' 'li' 'si'`（或数值 σ），**最大实部是 `'lr'`**。

**排查手法（重要）**：MATLAB 在中文 Windows 上的报错信息是中文，
在 Git Bash 里经 `-batch` 输出会变成乱码，完全读不出来。**不要靠读消息文本**，改抓标识符：
```matlab
try
    ...
catch ME
    fprintf('ERRID: %s\n', ME.identifier);   % 英文标识符，直接可搜
end
[wmsg, wid] = lastwarn;
fprintf('WARNID: %s\n', wid);
```
本次就是靠 `WARNID: MATLAB:eigs:NotAllEigsConverged` 与
`WARNID: MATLAB:eigs:IgnoredOptionIssym` 定位的两个问题。

## B2. `eigs` 在 `'lr'` 模式下不收敛（谱顶极度密集）

**现象**：`MATLAB:eigs:NotAllEigsConverged`，结果为空。

**根因（量级要算清楚）**：
矩阵尺度是 `1/h² ≈ 6.9×10⁵`（h ≈ 1.2 nm），而待求本征值 `λ = k0²n_eff² ≈ 484`。
也就是说想找的谱顶**只占整个谱宽的 ~1e-3**，且相邻模式的间隔远小于谱宽。
ARPACK 在 `'lr'` / `'la'` 模式下的 Krylov 空间分辨不出相邻模式。

**修法**：改用 **shift-invert** —— 给一个略高于谱顶的位移 σ
```matlab
sigma = k0^2 * (n_max + 0.1)^2;
[V, D] = eigs(A_int, n_req, sigma, eo);
```
它把谱顶的几个模式映射成"最占优"的几个，同时把间隔大幅拉开。
对三对角矩阵的 LU 分解是 O(N)，代价可忽略。

**附带发现**：**用数值 σ 时 `issym` 会被忽略**，并发出
`MATLAB:eigs:IgnoredOptionIssym` 警告。
这个警告本身无害，但会**淹没真正需要关注的收敛警告**，所以显式不要设它。

**怎么防**：用 `eigs` 求稀疏本征值时，先算一下**目标本征值与矩阵范数的比值**。
比值远小于 1 且目标在谱顶，就直接上 shift-invert，别浪费时间调 `maxit`。

## B3. Richardson 外推要求网格严格嵌套

**代码位置**：`src/solve_fdm.m`

用 `N` 与 `2N−1` 两种网格点数（**不是** `N` 与 `2N`）——
只有 `2N−1` 才严格包含 `N` 网格的全部节点，外推才干净。
外推式：`n_eff ≈ (4·n_eff(h/2) − n_eff(h))/3`。

**另一处关键**：界面处必须用**控制体内的 n² 精确平均**（亚格子平均），
不能直接取网格点所在层的 n²。否则折射率阶跃界面在网格移动时引入 O(h) 噪声，
收敛阶从 O(h²) 掉下来，**外推彻底失效，路径 3 永远对不到 1e-6**。

## B4. `eigs` 在本机对本尺度问题整体返回 NaN（不是不收敛，是解出 NaN）

**现象**：`MATLAB:eigs:NotAllEigsConverged` → 「0 个(共 2 个)特征值收敛…特征值为 NaN」。
连手工构造的 **5×5** 标度化三对角矩阵也一样；`'la'` 与 shift-invert 全部无效。

**与 B2 的区别**：B2 里 shift-invert 是**能救**的；这次连它也不收敛，直接给 NaN。
所以「照 B2 的修法上 shift-invert」这条路在这台机器上**已经失效**。

**代码位置**：2026-10-21 独立验证时另写的有限差分（`Mode_L1_V1.0/Model_Self_L1_7L_EBL_test.m` 内的 `fd_first`），
**不是** `src/solve_fdm.m` —— 也就是说，这条与「模型本身对不对」无关，是**本机 `eigs` 的问题**。

**修法**：放弃 `eigs`，改用 **Sturm 计数 + 二分** 求最大本征值。

- 对 `A − μI` 做 LDL（不选主元）分解，**负主元个数 = 小于 μ 的本征值个数**；
- 在 `[0, max(k0²n²)]` 上二分，直到区间宽度 < 1e-12。

**两个必须同时踩对的细节**（错一个就二分区间的端点全错）：

1. **矩阵必须按 h² 无量纲化**：对角 `−2 + k0²n²h²`、次对角 `1`。
   不归一化的话，Thomas 主元在 1e6 量级上相消，**符号判据直接失效**（主元变成随机噪声）。
2. **本征值的上界是 `max(k0²n²)`，不是 `max(diag(A))`** —— 后者含 `−2/h²`，比真上界低一大截，
   二分上界取错会把基模排除在区间之外，然后「找不到根」。

**顺带一个不能用的替代**：反迭代（inverse iteration）。它会收敛到**盒模式** ——
实测得到 `n_eff = 2.3728`、残差 3e-12，看着是完美的真本征对，实际是 p-clad（2.374）以下的伪模。
判据「n_eff 必须大于两侧包层折射率」能把它挡掉，但反迭代本身不可靠，不要拿它当备选。

**怎么防**：在本机跑任何基于 `eigs` 的稀疏本征求解前，先拿一个 **5×5 左右的小矩阵冒烟测试**；
返回 NaN 就直接转 Sturm 二分，不要在 `maxit`、`tol`、`sigma` 上浪费时间。
**阶段 3 的二维脊波导**如果还要用稀疏本征求解，开工第一件事就是做这个冒烟测试。

# C 类：判据与验证设计（★）

## C1. 判据要针对真正想验的东西

**现象**：`tests/t04` 有一项判据设为"延伸长度加倍后 Γ 变化 < 1e-12"，实测 3.2e-10，**判为失败**。

**根因**：这个残差的来源是**梯形积分的采样密度**，不是场尾截断。
`tail_dec` 加倍而每层采样点数不变 ⇒ 半无限层网格步长加倍 ⇒
复合梯形公式误差 `−(h²/12)∫w″dy` 约放大 4 倍。3.2e-10 完全是这个来源。

**修法**：拆成两条各验各的：
1. **截断充分性**：直接看**采样区间端点处的功率密度 / 峰值**（实测 1.5e-21，判据 < 1e-15）。
   这才是"场尾有没有被切掉"的直接证据。
2. **Γ 稳定性**：判据放宽到 1e-8，并在注释里写明残差的真实来源。

**怎么防**：把判据设在机器精度，等于逼人去调一个**没有物理含义的数字**。
判据的阈值必须能对应到一个明确的物理或数值来源。

## C2. 交叉验证必须逐个比数值，不能只比数量

见 A1。**模数一致**只说明"找到了同样多个根"，完全不保证"找到的是同一批根"。

## C3. 交付图的 md5 会变，但内容可能一字未改

**发现场景**：2026-10-16 复跑 `run_stage1` 后，`DS_Deve/out/` 的 4 张图 **md5 全部改变**：

```
fig1_three_way.png   3d7466b7…  →  765da544…
fig3_profile.png     37d265d4…  →  67f1f8a0…
t02_vnumber.png      a497e978…  →  3d27a491…
t03_thickness.png    fd0cf484…  →  8e94d22e…
```

看上去像"重跑把交付物改坏了"。**但逐像素比对的结果是**：

```
fig1_three_way.png   size=[810 1324 3]   maxdiff=0   ndiff=0
fig3_profile.png     size=[759 1353 3]   maxdiff=0   ndiff=0
t02_vnumber.png      size=[941 1313 3]   maxdiff=0   ndiff=0
t03_thickness.png    size=[718 1450 3]   maxdiff=0   ndiff=0
```

**四张图逐位相同。**

**根因**：MATLAB 的 `exportgraphics` 会在 PNG 内写入两个文本块：

```
tEXtSoftware       MATLAB, The MathWorks, Inc.
tEXtCreation Time  26-Sep-2026 16:51:22      ← 旧
tEXtCreation Time  16-Oct-2026 10:34:00      ← 新
```

**只有这一行时间戳变了**，像素数据完全一致。

**为什么这条重要**：本项目在 09-26 曾把交付图的 md5 当作基线写进文档
（`d91ff972…`，后改为 `e35c32f0…`）。按本条结论，
**任何人重跑一次，那个 md5 就会失效，而内容可能一字未改** ——
拿它当"交付物有没有被改动"的判据，**必然误报**。

**怎么防**：

1. **要判断图有没有变，比像素，不比 md5**：
   ```matlab
   a = imread('out/fig1.png');  b = imread('backup/fig1.png');
   maxdiff = max(abs(double(a(:)) - double(b(:))));
   ```
2. **验收前先把待核产物复制一份到工程目录**（别放 `%TEMP%`，那会被清理）。
   09-26 就吃过这个亏：备份件随临时目录一起被清除，新旧图只剩 md5 一个把手，
   **无法证明内容是否改变**。
3. md5 仍可用来查"文件有没有被动过"，但**不能用来判"内容有没有变"**。

## C4. 多瓣远场的 FWHM：同一个数字，两种含义

**发现场景**：2026-10-16 新增快轴远场发散角后，对 7 层结构三个模的读数。

```
TE0: FWHM = 23.95°   峰值角 =   0.00°   I(0°) = 1.000
TE1: FWHM = 34.83°   峰值角 =  -8.91°   I(0°) = 0.729
TE2: FWHM = 15.70°   峰值角 = -18.09°   I(0°) = 0.284
```

**TE2 的 FWHM 比基模 TE0 还窄** —— 这不代表 TE2 更准直。

**根因**：FWHM 判据是"自峰值向两侧各找第一个降到半高的点"。
对多瓣分布，读数取决于**瓣间凹陷相对于半高的深浅**：

| 情形 | 例子 | 判据行为 | FWHM 的含义 |
|---|---|---|---|
| 凹陷**浅于**半高 | TE1（0° 处 I = 0.73） | 两侧半高点跨过中央凹陷 | **整个包络的宽度**（横跨两瓣） |
| 凹陷**深于**半高 | TE2（0° 处 I = 0.28） | 从峰值向两侧很快降到半高以下 | **只是峰值那一瓣的宽度** |

**同一个物理量、同一套代码，在不同模上给出两种含义的数。**

**怎么防**：

- **报 FWHM 时必须带上峰值角**（`th_pk`）。偏离 0 就说明角分布偏心/多瓣，读数要打问号。
- 更根本的办法是**画图**：远场角分布图上画一条半高判据线，一眼看出"这个数是从哪量到哪"。
  本项目已内建（`fast_field.png`）。
- 这与 A5 的 Γ 口径、D4 的伪根同类：
  **"同一个公式在不同输入下含义不同"** —— 定义必须连同**适用范围**一起给出。

# E 类：绘图（★，但极易误判为物理错误）

## E1. `patch` 给固定高度会撑爆纵轴

```matlab
patch([lo hi hi lo], [0 0 1e3 1e3], ...)   % ✗ ylim 被顶到 1000
```
三条曲线全被压成贴地直线，图看起来像"完全没有模式"。

**修法**：用 `xregion(lo, hi, ...)` —— 它自动铺满当前纵轴、**不改变 ylim**。

## E2. 绘图窗口必须覆盖整个外延结构

fig3 最初设 `ymax = 1.35`，但有效芯区（InGaN 波导 + QW）在 **y ≈ 1.20–1.41**，
峰值正好被切在窗口边缘。

**症状极具误导性**：曲线在窗口右边界急剧上升，看起来像"**模场往 p 侧发散**"
（一个物理上荒谬但足以让人去查求解器的现象）。
实际只是没画全。

**怎么防**：画模场前先打印 `yb`（各层 y 区间），确认窗口覆盖
`[第一个有限层下沿 − 若干穿透深度, 最后一个有限层上沿 + 若干穿透深度]`。

---

## E3. 两个绘图/UI 的静默行为

**（1）`uitable` 导不出图**

`uitable` 是 **UI 控件**，不是坐标轴内容 —— `exportgraphics` / `print` / `saveas`
**都导不出它**。模型在 `'save'` 模式下能导出主图与远场图，但数据表格不会出现在 PNG 里。

**怎么防**：需要留档的表格，要么另外写 CSV，要么从返回的**结构体**里取数
（本项目 `modes(k).P_layer`、`modes(k).ff` 等字段里都有）。

**（2）`yyaxis` 的两根轴是分层渲染的**

双纵轴图（左轴折射率、右轴 \|φ\|²）中，**右轴整体盖在左轴之上，与绘制先后无关**。

本项目踩过的形态：把"层底色"用 `patch` 画在**右轴**上，
结果**折射率黑线被整条盖成灰色** —— 图看起来像"折射率画错了"。
修法：层底色画在**左轴**（与折射率线同轴）。

**怎么防**：双轴图里，**同一类元素画在同一根轴上**（底色与轮廓同轴）。
`patch` 的 `HandleVisibility` 设 `'off'`，可避免它污染图例。

## E4. `uitable` 的"框"和"内容"是两回事

**代码位置**：`Mode_L1_V1.0/Model_Self_L1_7L_EBL.m` §5 制表段

**现象**：把 uitable 的**控件尺寸**拉大之后，**表格内容纹丝不动** —— 单元格网格仍挤在
左上角一小块，右侧和下方全空成控件背景；同时数值被截断成 `2.4...`、`1.00...`、`94...`。

```
控件 1464×550，7 列，但每列只有约 63 px（内容总宽约 460 px）
   → 右边空 ≈ 1000 px，下方空 ≈ 300 px
数值 '2.41712846' 约需 105 px（16 pt）—— 装不下，显示 '2.4...'
```

**根因**：里面有两层尺寸，**互相独立**：

| 层 | 由谁决定 | 默认行为 |
|---|---|---|
| **控件**（外框） | `Position` | 设多大就多大 |
| **内容**（单元格网格） | `ColumnWidth` | **`'auto'` —— 只按内容算宽，与控件尺寸无关** |

所以"把 `Position` 调大"只放大了外框，内容不跟随；**外框越大，空白越多**，
每个格子的可用宽度也没变，该截断的照样截断。

**另一条硬限制**：传统 figure 的 uitable（`matlab.ui.control.Table`）

- **没有 `RowHeight` 属性**（实测报 `MATLAB:hg:InvalidProperty`）
- `'fit'`（自动填满）是 App Designer / uifigure 专有，传统 figure 用会报
  `MATLAB:ui:uifigure:UnsupportedAppDesignerFunctionality`

⇒ **列宽可以显式控制，行高不可控**（永远由字体决定，16 pt 约 28 px）。

**修法**（本项目的做法，见 `relayout_tables`）：

1. **列宽显式等分**：`'ColumnWidth', num2cell(repmat(floor(可用宽/列数), 1, 列数))`
2. **控件高度按行数贴合**：`高 = (数据行 + 表头) × 单行高 + 余量`，行高取 32 px
3. **窗口尺寸也随之贴合内容**，别再留一个大框
4. **窗口拉伸时重排**：把重排函数挂到 `fig.SizeChangedFcn`，否则宽度变了列宽不跟随

**怎么防**：

- 改 uitable 尺寸前先问一句：**我要改的是"框"还是"内容"？**
- **`ColumnWidth` 不设，控件就永远是"小表格 + 大空白"。**
- 行高不可控 ⇒ **别让控件比内容高太多**；"表格纵向铺满大窗口"在这个控件上做不到
  （除非把字号加到 40 pt）。
